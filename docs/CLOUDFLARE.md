# Cloudflare Deployment

The main website (`apps/web`) is deployed as a **Cloudflare Worker with Assets** — not Cloudflare Pages.
This is required because `@astrojs/cloudflare` v14+ generates Workers + Assets output (`dist/server/` + `dist/client/`), which is incompatible with the Pages deployment model.

---

## Architecture

| Layer | Technology |
|---|---|
| Worker entry | `apps/web/dist/server/entry.mjs` (generated by Astro build) |
| Static assets | `apps/web/dist/client/` (generated by Astro build) |
| Config | `wrangler.toml` at repo root |
| CI/CD | Cloudflare Workers built-in Git integration |

---

## `wrangler.toml` (repo root)

```toml
name = "wedding-web"
main = "apps/web/dist/server/entry.mjs"
compatibility_date = "2024-09-23"
compatibility_flags = ["nodejs_compat"]

[assets]
binding = "ASSETS"
directory = "apps/web/dist/client"
```

The paths point to build artifacts — they only exist after `astro build` runs.

## Cloudflare Workers project settings

### Build & Deployments

| Field | Value |
|---|---|
| Build command | `pnpm install --frozen-lockfile && pnpm --filter @wedding/web build` |
| Deploy command | `npx wrangler deploy` |
| Version command | `npx wrangler versions upload` |
| Root directory | `/` |

### Environment variables (build-time)

| Variable | Notes |
|---|---|
| `NODE_VERSION` | `22` — required so Cloudflare activates Corepack + pnpm |
| `PUBLIC_SUPABASE_URL` | Baked into static HTML at build time |
| `PUBLIC_SUPABASE_ANON_KEY` | Baked into static HTML at build time |
| `SUPABASE_URL` | Available to API routes at runtime |
| `SUPABASE_ANON_KEY` | Available to API routes at runtime |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret — available to API routes at runtime |
| `ASAAS_API_KEY` | Secret — runtime only |
| `ASAAS_WEBHOOK_TOKEN` | Secret — runtime only |
| `ASAAS_SANDBOX` | `false` in production |

## Custom domain

Domain: `raissaefelipe2026.com.br`

DNS is fully managed by Cloudflare. The custom domain is registered in:
**Workers project → Settings → Domains & Routes → Custom Domains**

Cloudflare automatically creates and manages the DNS records when a custom domain is added here. Do not add CNAME records manually.

Also add `www.raissaefelipe2026.com.br` as a second custom domain on the same Worker.

## Manual deploy (one-off)

If CI/CD is unavailable, deploy manually from the repo root using a Cloudflare API token:

```bash
# Build
pnpm --filter @wedding/web build

# Deploy (type in terminal — do not share the token)
CLOUDFLARE_API_TOKEN=<token> npx wrangler deploy --config apps/web/dist/server/wrangler.json
```

Create an API token at: **Cloudflare dashboard → My Profile → API Tokens → Create Token → "Edit Cloudflare Workers" template**.

## GitHub Actions (alternative CI/CD)

A workflow exists at `.github/workflows/deploy-web.yml` that also handles deployment via GitHub Actions, as a fallback if Cloudflare's built-in CI/CD is unavailable. It requires these GitHub repository secrets:

- `CLOUDFLARE_API_TOKEN`
- `CLOUDFLARE_ACCOUNT_ID`
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- `PUBLIC_SUPABASE_URL`, `PUBLIC_SUPABASE_ANON_KEY`
